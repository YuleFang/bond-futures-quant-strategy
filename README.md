# 小窗口股票行情监控工具

一个可独立启动、可关闭的紧凑桌面窗口：同时监控配置中的 3~5 只股票，定时刷新名称/代码、现价、当日涨跌幅、近1分钟涨幅与数据状态；当涨幅突破阈值、或日内 1 分钟 MACD 出现金叉/死叉时，在**屏幕右下角**弹出不阻塞刷新的提醒。界面采用磨砂玻璃（Skeuomorphic Glass）风格，只显示文字状态、**不绘制任何图表**。纯 Python 标准库实现，零第三方依赖。

| 文件 | 说明 |
|---|---|
| `config.json` | 全部配置项（股票列表、数据源、刷新/阈值/窗口/提醒参数） |
| `core.py` | 纯逻辑层：配置校验、快照行情解析、涨幅计算、告警判定与去重、当日涨幅「突破前确认」门控；另含独立的 1 分钟 K 线解析、MACD 计算与离散信号状态机 |
| `app.py` | 界面与调度：Canvas 自绘玻璃窗口、两个独立后台线程（5 秒快照 / 分钟级 K 线）、行内角标、右下角非模态提醒窗 |
| `README.md` | 本文档 |

## 界面风格（磨砂玻璃）

- 无边框大圆角玻璃卡片、暖米色半透明面板、橙色柔光球、胶囊形行情行、近黑文字；数字用 Segoe UI、中文用微软雅黑。窗口用色键透明实现圆角，若平台不支持则降级为实色窗口，功能不受影响。
- 顶部：`MARKET WATCH · 行情监控` 小标签、「自选行情」标题、**大号最后更新时间**、橙色柔光，右上角圆形 `×` 关闭按钮。
- 中部：每只股票一个玻璃胶囊，左侧为名称 / 代码 / 状态，右侧为现价 / 当日涨跌幅 / 近1分钟涨幅；行高按 3~5 只自动适配。
- 每只胶囊第三行中部有一个 **MACD 状态角标**（`MACD金叉` 暖红 / `MACD死叉` 墨绿 / `预热 n/35` / `冷却中` / `今日已满`（限流生效后才有）/ `分钟线失败` / `静默`），复用行内空白、不新增行高，5 只股票也不挤压。
- 列表下方一行小字标注两项涨幅的计算基准；底部胶囊显示连接状态与「刷新间隔 · 数据源 · 时段」；顶部副标题追加 `1mMACD n/N 就绪` 汇总。
- A 股配色涨红跌绿；失败/延迟时整行文字置灰、胶囊变暗。
- 窗口无系统边框（不进任务栏），**按住面板空白处可拖动**；右上角 `×` 或 `Esc` 关闭。
- 提醒窗**固定在屏幕右下角**（留出任务栏空间），多条时向上堆叠但始终贴右侧；不抢焦点、不阻塞主窗口刷新。两类提醒（涨幅告警 / MACD 状态）共用同一份玻璃卡片布局，高度 380；因窗口变高，同屏最多条数受屏幕高度限制（1080p 为 2 条、768p 为 1 条）。
- 卡片底部固定短免责「指标状态提示 · 非投资咨询 · 数据可能延迟、指标具滞后性 · 不构成投资建议」，按「 · 」**折成两行完整渲染**，不会在 340px 宽度内被裁切或用省略号截断。

## 启动与关闭

**请务必在 PowerShell 中启动**（Windows 商店版 Python 3.11 自带 tkinter 8.6）：

```powershell
cd "C:\Users\Administrator\WorkBuddy\实验室"
python -c "import sys, tkinter; print(sys.version, tkinter.TkVersion)"   # 应为 3.11.9 / 8.6
python app.py
```

> ⚠️ 环境里另有一个 Bash/PATH 下的 Python 3.13.14（vendored 精简版），**不含 tkinter**。在 Git Bash 中执行 `python app.py` 会看到「当前 Python 缺少 tkinter。请在 PowerShell 中使用 Python 3.11 启动」并以退出码 2 结束，这是解释器问题，不是程序问题。请使用 PowerShell。

关闭方式：主窗口右上角圆形 `×` 或 `Esc` 键，走同一清理流程（停止取数线程、取消定时器、销毁全部窗口）。提醒窗用其右下角圆形 `×` 或等待自动消失；主窗口在提醒窗存在期间照常刷新。

## 计算基准（界面内也标注了口径）

| 指标 | 公式 | 基准来源 |
|---|---|---|
| 当日涨跌幅 | `(现价 − 昨收) / 昨收 × 100%` | 昨收取行情接口原始字段（腾讯 `f[4]` / 新浪 `f[2]`），不使用接口自带的涨跌幅作为判定值，仅作偏差 > 0.05 个百分点时的日志交叉校验 |
| 近1分钟涨幅 | `(现价 − P_ref) / P_ref × 100%` | `P_ref` = 本地滚动快照中「观测时间戳 ≤ 当前时间 − 60 秒」的最近一条有效现价 |

- 快照只记录有效报价；刷新间隔 5 秒时 `P_ref` 的时点误差不超过 1 个刷新间隔。
- 快照不足 1 分钟 → 近1分钟列显示 `计算中`，**不参与告警判定**；跨日/隔夜、昨收突变（除权或数据修正 > 1%）会清空该股快照并重置其告警锁，避免用除权前价格算出虚假涨幅。
- 昨收 ≤ 0、现价 ≤ 0、停牌形态（现价=昨收 且 今开=0 且 成交量=0）→ 显示 `—`，不写快照、不判定。
- 所有时间按北京时间（UTC+8）；A 股配色：涨红、跌绿；价格以 `¥` 显示。
- 上表是**价格涨跌幅**口径；MACD 金叉/死叉是另一套基于 1 分钟 K 线的指标状态，口径见「日内 1 分钟 MACD 信号」章节，两者互不影响。

## 数据状态

- 顶部大号数字显示最后更新的 `HH:MM:SS`；底部玻璃胶囊显示 `连接: 正常` 与 `5s · 腾讯 · 盘中`，另有 `更新中` 瞬时状态。
- `失败: <原因>`：网络超时、HTTP 错误、DNS、解析整批失败等；**保留上一轮数值并整行置灰**，绝不清零、绝不冒充实时；若距上次成功超过 `stale_threshold_sec` 则升级为 `延迟`。
- `延迟(行情时间戳过旧 / 行情未更新 / 行情非今日)`：盘中数据未按时推进；对应行显示原因并置灰。
- `<时段>·暂停取数`（默认）：`fetch_only_in_session=true` 时，周末 / 盘前 / 集合竞价 / 午休 / 盘后**完全不发任何 HTTP**——价格快照与 1 分钟 K 线都不拉取。界面保留上一轮价格与涨跌颜色，行内状态标「<时段>·暂停」，连接栏明确显示暂停；盘中一到自动恢复取数。仅 `data_source="mock"`（纯离线、不联网）不受此限制。
- 把 `fetch_only_in_session` 设为 `false` 则恢复旧行为：盘后仍按间隔轮询，连接栏显示 `非交易时段·<时段>(静态行情)`，便于复盘，代价是持续请求。
- 单只股票异常（无数据、停牌、字段解析异常）只影响该行，错误原因写在状态位置，不拖垮整批。
- 交易时段按北京时间判定：周末休市；`<9:15` 盘前；`9:15~9:30` 集合竞价；`9:30~11:30`、`13:00~15:00` 盘中；`11:30~13:00` 午休；`>15:00` 盘后。
- **已知局限：不内置法定节假日日历**。节假日若落在工作日，程序仍按「盘中」判定并联网取数（不会因节假日自动暂停），只是行情时间戳不推进会保守标注「延迟」或「行情未更新」，不谎称实时。如需彻底静默，可在假日手动把 `fetch_only_in_session` 保持 `true` 之外，再关闭窗口。
- **分钟线请求失败只影响该股的 MACD 角标**（显示 `分钟线失败`），不改连接状态、不置灰整行、不影响两项涨跌幅告警；两路数据在独立线程中取数、只在主线程汇合于角标与提醒队列。

## 告警规则

> 涨幅告警与 MACD 状态提示是**两条独立链路**：MACD 是离散交叉事件，使用自己的事件去重状态机，不与涨幅告警合并、不互相排队干扰。本节只讲涨幅告警，MACD 见下一章。

- 触发：任一股票 `当日涨幅 > 2%` 或 `近1分钟涨幅 > 1%`（严格大于，阈值来自配置）。**当日涨幅另需满足下方「突破前确认」**，近1分钟涨幅不受该门控影响。
- 去重：每个 `(股票, 条件)` 独立上锁。触发后只要该指标仍 `≥ 阈值` 就不再提醒；**回落到阈值以下（严格小于）才解锁**，之后再次上穿才重新提醒。`== 阈值` 视为仍 ≥ 阈值，保持上锁。指标为 `计算中/—` 期间冻结锁状态，不判定、不误解锁。
- 合并：同一轮同一股票新触发的两个条件**只发一条**提醒，触发条件文本合并；若其中一个条件已上锁未恢复，只发新触发条件的那一条（但该条仍完整展示两个涨跌幅数值）。当日条件被前置窗口抑制时也一样——只发近1分钟那一条，触发条件文本不会带上当日涨幅。
- 提醒窗内容：股票标识 `名称 (代码)`、现价、当日涨跌幅、近1分钟涨幅、触发条件、触发时间（北京时间 `YYYY-MM-DD HH:MM:SS`）。**固定在屏幕右下角**、置顶、非模态，不调用 `grab_set` / `wait_window` / `messagebox`，不阻塞主窗口刷新；多条排队、可手动关闭或自动消失。
- 恢复示例（`day_change_precheck_sec=0` 时）：`100 → 103（首次触发，上锁）→ 103.5（不提醒）→ 101.9（<2%，解锁）→ 103.2（再次提醒一条）`。

### 当日涨幅的「突破前确认」（默认前 5 分钟）

用户要求：**日内涨幅超 2% 之前，前 5 分钟必须都在 2% 以下**。实现为 `core.DayChangeGate`，与去重锁完全分离，只作用于 `day` 条件。

| 判定项 | 口径 |
|---|---|
| 观测来源 | 工具自身每轮价格快照算出的当日涨幅，**不是**行情分钟线；与近1分钟涨幅同源、同刷新间隔 |
| 「在 2% 以下」 | 观测值 `≤ 阈值` 即算下方；触发仍用严格 `> 阈值`，两者互补不冲突 |
| 满足条件 | 上穿之前已**连续** `day_change_precheck_sec`（默认 300 秒）所有观测都在阈值下方 |
| 计时清零 | 出现 `> 阈值` 观测、观测值为 `计算中/—`、或相邻两轮间隔超过 `max(15s, 3×刷新间隔, 2×请求超时+刷新间隔+2)`（取数失败、午休、非盘中暂停取数）。上界随超时联动，避免主源超时、备用源也慢时把一次正常取数误判成中断 |
| 抑制时 | **不上锁、不提醒、不消耗触发机会**；回落并重新满足后仍可触发，日志记 `本次抑制且不上锁` |
| 跨日 / 除权 | `reset_symbol` 会一并清空该股前置历史，旧观测不能充当今天的前 5 分钟 |
| 界面 | 已站上阈值但前置窗口未满时，行内状态显示 `待确认m:ss` 倒计时；窗口一满即恢复正常判定 |

由此产生三个**必须知道**的行为：

1. **启动后 5 分钟内当日涨幅不会弹窗**：程序刚启动没有历史，无法证明「前 5 分钟都在下方」。9:30 启动则约 9:35 起才有资格。
2. **启动时就已经在阈值上方的股票不会弹窗**：没有「从下方上穿」这个事件；必须回落到 `≤2%` 并连续待满 5 分钟，之后再次上穿才提醒。持续高位震荡不提醒。
3. **午休 / 非盘中暂停取数后重新计时**：下午 13:00 恢复取数后，约 13:05 起才重新具备资格。

想回到旧的「上穿即提醒」，把 `day_change_precheck_sec` 设为 `0`；想缩短等待，设为 `60`（1 分钟）等较小值。改完**重启窗口**才生效。

## 日内 1 分钟 MACD 信号（指标状态提示）

**定位**：这是一个「指标状态提示工具」，只在 1 分钟 K 线的 MACD 发生金叉/死叉时报告**指标计算结果的文字状态**，不是证券投资咨询服务、不是荐股软件，也不绘制分时图或 MACD 柱图。所有文案只描述指标状态，不含任何买卖动作词、价位、数量或收益承诺。

### 数据源与「绝不混源」

| 角色 | 接口 | 说明 |
|---|---|---|
| 主源 | 新浪 `https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData?symbol=<code>&scale=1&ma=no&datalen=1200` | 顶层是数组，元素含 `day`（`YYYY-MM-DD HH:MM:SS`）与字符串 `close`；一次约 5 个交易日 1000+ 根；无效代码返回字面量 `null` |
| 备用 | 东方财富 `https://push2his.eastmoney.com/api/qt/stock/trends2/get?secid=<...>&ndays=5&...` | `data.trends` 为字符串数组，逗号切分 `[0]` 时间、`[2]` 收盘价；`secid`：`sh→1.`、`sz→0.`、`bj→0.` |

- 主源超时 / 返回 `null` / 解析为空 / 当日 0 根 / 全平停牌序列时，才整段切换备用源。
- **两个源的分钟切分口径不同**（同一分钟收盘价可能差 0.1~1 元）。切源时会丢弃旧源的全部序列、用新源完整序列从头重算 EMA，**绝不拼接或混算**；切换也不会导致同一交叉重复提醒。
- 每分钟每只股票最多 1 次请求，多只串行限速（默认间隔 0.4 秒）。
- **非盘中零联网**：`fetch_only_in_session=true`（默认）时，盘前 / 集合竞价 / 午休 / 盘后 / 周末，价格快照与分钟线都不发请求；价格线程与分钟线线程各自独立判断，互不等候。设为 `false` 才允许盘后继续拉取（此时只把角标置「静默」，绝不发信号）。

### 计算口径（方法与局限）

```
DIF  = EMA(CLOSE, 12) − EMA(CLOSE, 26)
DEA  = EMA(DIF, 9)
BAR  = 2 × (DIF − DEA)          # A 股软件口径；国际平台常不乘 2，不影响交叉位置
金叉 ⇔ (DIF_t > DEA_t) ∧ (DIF_{t−1} ≤ DEA_{t−1})
死叉 ⇔ (DIF_t < DEA_t) ∧ (DIF_{t−1} ≥ DEA_{t−1})
```

- EMA 用 `adjust=False` 全量递推，输入是**已收盘的 1 分钟 K 线收盘价**；盘中未收盘的那根不参与判定，跨日/午休断点不与前一交易日末根比较。
- 通达信/同花顺的「分时 MACD」本质上就是 1 分钟 K 线收盘价的 MACD，因此保持标准 `(12,26,9)` 才能与看盘软件对照；靠过滤条件降噪，而不是改参数。
### 为什么同花顺 MACDFS 从 09:30 就有值

分时 MACD 本质上仍是 **1 分钟收盘价的 MACD(12,26,9)**，公式与日线 MACD 相同。看盘软件做了两件我们原来没做的事：

1. **EMA 不在交易日边界重置**：把分时序列当作连续时间流，当日第一根继承前一交易日的 `EMA12 / EMA26 / DEA` 状态（等价于用前 N 日的分钟线做预热），所以开盘瞬间 DIF/DEA 就衔接昨尾、柱一上来就有正常高度，而不是从 0 慢慢爬。
2. **不做预热屏蔽**：第一根分时数据一到就照算照画，前几十根即使还在收敛也照常显示，没有「计算中」空白区。

截图里 09:30 起就有密集红绿柱和两条线，正是这两点叠加的结果。本工具已按第 1 点改造为默认 `warmup="prev_day"`；第 2 点因为是**文字信号工具而非画图工具**，改为「指标立即有效、信号仍走强降噪」，避免开盘高频擦线交叉刷屏。

- **两档预热 `macd.warmup`**（默认已切为 `prev_day`）：
  - `prev_day`（默认）：取新浪返回的完整多日序列（约 1200 根）连续递推，当日首根继承前日末态。EMA 在开盘前早已收敛，**09:31 第一根 K 线落地即具备有效指标**，与同花顺 MACDFS 一致。预热门槛按「递推序列总根数」判断，天然达标，默认不再出现「预热 n/35」。
  - `same_day`：只取当日 K 线，首根 `EMA12=EMA26=close₁`、`DIF₁=0`、`DEA₁=0`。适合与只看当日序列的口径做数值对照，但需等到当日第 35 根（约 10:05）才充分预热。
  - **如何对照自己的软件**：把弹窗同一分钟的 `DIF / DEA / 柱` 与看盘软件的分时 MACD 比对；数值接近 → 口径一致；差异明显 → 把 `macd.warmup` 切到另一档并重启窗口。注意 `prev_day` 的绝对值会受历史序列长度影响，交叉时点也可能与软件略有差异。

### 判定与降噪（六重）

1. **0 轴顺势**：金叉要求 `DIF>0`、死叉要求 `DIF<0`。
2. **0 轴黏合过滤**（本次新增）：要求 `|DIF| ≥ 现价 × min_dif_ratio`（默认 `0.0001`）。开盘阶段两线频繁贴合会产生大量「擦线交叉」，用**相对现价**的阈值剔除，避免 9 元股与 1400 元股量纲差异导致固定阈值失效；设 `0` 可关闭。默认刻意保守，调高会误杀缓慢趋势的正常交叉。
3. **柱确认**：交叉后需柱连续 `bar_confirm_bars`（默认 2）根同向且绝对值放大；中途反向或缩小即丢弃候选。
4. **冷却**（仅下午）：同股两次提醒间隔 ≥ `cooldown_min`（默认 15 分钟）。
5. **每日上限**（仅下午）：每只在限流时段内最多 `daily_max`（默认 3）条。抑制即丢弃、不排队补发。
6. **时段窗口**：默认覆盖 `09:31–11:30` 与 `13:01–15:00`（全部盘中）；想更保守可改回 `[["09:45","11:25"],["13:05","14:30"]]`。去重键为 `(股票, 交易日, 交叉所在分钟, 方向)`；跨日、除权（昨收突变）、停牌会重置该股计算态。

#### 冷却 / 每日上限：上午无效，下午开始生效

开盘阶段是日内波动与交叉最密集的时段，15 分钟冷却和 3 条上限会把早盘的连续信号压掉，因此这两条改为**按时段生效**：

| 时段 | 0 轴顺势 / 黏合过滤 / 柱确认 / 时段窗口 / 同键去重 | 冷却 / 每日上限 |
|---|---|---|
| `09:31 ~ throttle_start` 之前（默认整个上午） | 生效 | **不生效** |
| `throttle_start` 起（默认 `13:00`，下午） | 生效 | **生效** |

- 边界由 `macd.throttle_start`（`HH:MM`）决定，用北京时间墙钟判断；`session_windows` 仍独立控制哪些分钟允许出信号。
- 上午发出的信号**不启动冷却计时**，也不占用下午额度（默认 `count_morning_in_daily_max=false`）：下午第一条信号不会被午休前的信号误挡，下午重新有 `daily_max` 条额度。把该键设为 `true` 则改为全天累计，上午发满 3 条后下午整段静默。
- 想退回「全天限流」的旧行为，把 `throttle_start` 设为 `"09:30"` 即可。
- **全天不变的四层过滤 + 去重仍在**：上午不是完全放开，只有「冷却、每日上限」两条被摘掉；另外 `alert_max_visible` / `alert_max_queue` 仍限制同屏弹窗数与队列长度。实测某日 1 分钟 K 线「无过滤 13 次交叉 → 0 轴过滤 4 次」，说明上午实际可发出的信号量仍然有限。

**「开盘即有效」≠「开盘就刷屏」**：指标数值与角标从 09:31 起可用；上午仍需连过 0 轴顺势、黏合过滤、2 根柱确认，下午再叠加 15 分钟冷却与 3 条上限。硬上限只在下午生效，因此早盘的信号条数由前四层过滤决定，下午最多再加 3 条/只。

### 滞后性与状态标注

- 一条信号的时间成本 ≈ 该分钟 K 线收盘（最多 1 分钟）+ 柱确认 2 根（约 2 分钟）+ 接口与轮询延迟（约数秒），因此**相对现价滞后约 1~3 分钟**；MACD 本身是两次平滑的结果，天然滞后，金叉/死叉常出现在波段中后段。`prev_day` 模式下最早可能的交叉在 09:32（首根 09:31 没有同日前一根可比），最早弹窗约 09:34。
- 角标状态：`MACD金叉` / `MACD死叉` / `预热 n/35`（仅 `same_day` 档或 mock 离线帧会出现；真实 `prev_day` 下跨日序列天然达标）/ `冷却中` / `今日已满`（这两个只会在 `throttle_start` 之后出现）/ `分钟线失败` / `静默`。
- 帧超过 `max_frame_age_sec`（默认 120 秒）即冻结，不基于陈旧数据发信号；**非交易时段的静态行情绝不发出金叉/死叉**。

### 局限与数据缺陷（请务必阅读）

- 1 分钟级 MACD 噪声极大，震荡段交叉频繁；强降噪在减少打扰的同时**必然会漏掉部分信号**。
- 公开接口可能延迟、缺根、切分口径与看盘软件不同；两源之间也存在差异。工具不内置法定节假日日历，靠时段与时间戳门控保守处理。
- 本工具**不预测走势、不保证信号准确、不承诺任何收益**，也不提供任何买卖时机建议。指标状态与价格涨跌幅是两套独立口径，不可互相替代。
- **A 股 T+1 机制说明（仅机制陈述，非操作建议）**：A 股实行 T+1，当日新增持仓须次一交易日方可流转；通常所说的日内「做 T」依赖隔夜底仓完成日内闭环，并非当日回转，且受底仓数量、交易成本与波动幅度约束。自 2024 年起融券日内回转已被限制。可转债、跨境/债券/黄金 ETF 等才是原生 T+0 品种。
